Platform for Business Orientated
Event-Driven Applications

FlowCatalyst is a multi-tenant event router and webhook delivery platform. Your applications publish a business event once. FlowCatalyst matches it to subscriptions, delivers it as a signed webhook, retries failures, rate-limits and orders deliveries, and gives operators one console to watch and intervene. Around that core it provides the identity your applications share: an OAuth2/OIDC provider with federated login, roles and permissions, and service accounts.

Everything You Need to Build

A complete platform foundation with identity, events, and operations built in.

Developer Friendly Deployment

fcdev runs the whole platform locally in one process with an embedded PostgreSQL: no Docker and no queue service. In production, fc-server is one binary whose subsystems you switch on with environment variables.

Multi-Client Architecture

Clients are tenants. Events, subscriptions, dispatch pools and users can be scoped to a client, and a client-scoped user never sees another client's data. Three tiers cover platform staff, partners and tenants.

Built-in OIDC Provider

A full OAuth2/OIDC provider with federation to Microsoft Entra, Google, or any standards-compliant OIDC provider. Passkeys, two-factor authentication, and service accounts with the client credentials grant.

Centralized Control Plane

Manage applications, users, roles, event types, subscriptions, dispatch jobs, scheduled jobs and functions from one web console, with an audit log of every administrative action.

Reliable Event Delivery

At-least-once delivery with ordering within a message group, automatic retries with backoff, dispatch pools that cap concurrency and rate, and HMAC-SHA256 signed webhooks.

Maximum Observability

Filter events and dispatch jobs, read every delivery attempt, and requeue, cancel or complete failed jobs from the console. Prometheus metrics and a router dashboard are built in.

SDKs and Transactional Outbox

SDKs for TypeScript, Laravel, Java and Go write events inside your own database transaction, sync your event types, subscriptions and roles from code, and verify webhook signatures.

Scheduled Jobs

Cron-driven jobs delivered as signed requests, with locking so exactly one instance fires each tick, manual firing, and a history and log for every run.

Functions

Small programs in Go, Rust or TypeScript that the platform stores, versions and runs in a WebAssembly sandbox, wired to events, schedules and HTTP with no server of yours to run.

Identity Built In

FlowCatalyst is a full OAuth2/OIDC provider. Your applications never store credentials or run login screens, and you do not need a separate Keycloak or Auth0 deployment.

  • Federation with Microsoft Entra, Google, and any standards-compliant OIDC provider
  • Passkeys and two-factor authentication with authenticator apps or email PINs, and recovery codes
  • Service accounts with the client credentials grant for machine-to-machine auth
  • Per-domain sign-in that routes each email domain to its identity provider or to password login
  • Role-based access control with four-segment permissions, delegable to a client's own administrators
  • Three tiers: Anchor (platform staff, every client), Partner (a set of clients), Client (exactly one tenant)

See Everything. Fix Anything.

Designed for maximum observability. Every event, every dispatch job, every delivery attempt is visible and actionable.

  • Search & filter events and dispatch jobs by application, event type, status, client, message group and time range
  • Requeue failed deliveries, one job at a time or in bulk, with a full retry budget
  • Resolve failures from the console: read every attempt, then requeue, cancel or mark the job complete
  • Audit log and login attempts record every administrative action and every sign-in, human or machine

One Place to Manage Everything

A centralized control plane for applications, users, events, and operations.

The path of an event
Your application → Platform API → Stream processor → Dispatch scheduler → Queue → Router → Your endpoint

Your application publishes an event, usually through the SDK's transactional outbox. The stream processor creates one dispatch job for each matching subscription, the scheduler queues it on PostgreSQL or SQS FIFO, and the router applies each pool's concurrency, rate limit and ordering before the platform signs and delivers the webhook. All state lives in PostgreSQL.

Applications

Register the systems that publish and consume events. Each declares its event types, subscriptions and roles in code and syncs them on deploy

Event Types

Four-part codes with a JSON Schema and versions, used to route events and to filter them in the console

Subscriptions

Bind event types to an endpoint, with an ordering mode, retries, a timeout and a dispatch pool

Users & Roles

Role-based access control with four-segment permissions, delegable to a client's own administrators

Clients

Tenants with their own users, scoped events and subscriptions, and the applications they are entitled to

Dispatch Jobs

One delivery each: watch its status, read every attempt, then requeue, cancel or complete it

Dispatch Pools

Delivery budgets that cap concurrency and rate, so one slow or flooded consumer cannot starve the rest

Scheduled Jobs

Pause, resume and fire jobs by hand, and inspect every run and its log

Audit Log

Every administrative action and every login attempt, success or failure, human or machine
